## Персональный ИИ-ассистент для управления задачами (Telegram-бот + веб-кабинет)

### 2. Контекст и бизнес-цель

**Проблема.** Поток рабочих и домашних дел нигде не фиксируется и держится в голове. Следствие — когнитивная перегрузка, усталость, постоянное ощущение недоделанности и «что-то забыл».

**Цель.** Создать единый «внешний мозг»: пространство, куда можно мгновенно (текстом, голосом, картинкой) сбрасывать задачи, идеи и заметки в любом — сыром или структурированном — виде. ИИ распознаёт, структурирует и раскладывает ввод по сущностям, а по запросу выдаёт план дня и аналитику.

**Ценность.** Снижение когнитивной нагрузки; ничего не теряется; ясная картина «что сделано / что впереди»; выгрузил мысль — можешь про неё забыть.

---

### 3. Роли

- **Пользователь** (единственный) — владелец данных, работает через Telegram и веб-кабинет.
- **ИИ-ассистент** — распознаёт ввод, структурирует, отвечает, предлагает связи; действует автономно в рамках заданных правил.
- **Система** (бэкенд + БД + веб) — хранение, синхронизация, авторизация, планировщик, резервное копирование.

---

### 4. Границы решения (Scope)

#### 4.1 Входит в MVP
- **Каналы:** Telegram-бот (диалоговый ассистент) + веб-кабинет (структурированное управление + дашборд + настройки). Синхронизированы через общую БД.
- **Ввод:** текст, аудио (STT → текст), изображения (OCR → текст); ручное прикрепление медиа к записям.
- **Сущности:** Задачи, Идеи, Заметки, Проекты; Сферы (теги).
- **Сценарии ассистента:** добавление/парсинг, план на день, аналитика дня, поиск/выборки, смена статуса, лёгкие правки.
- **Гибридное связывание** сущностей (детерминированный костяк + ИИ-подсказки).
- **Настройки уведомлений** (по умолчанию — молчит; опция — плановый утренний отчёт).
- **Авторизация** веб-кабинета (логин + пароль).
- **Резервное копирование**, недоступное для изменения ИИ.

#### 4.2 НЕ входит в MVP (backlog)
- Глубокое «понимание» изображений (сцены, объекты) — только извлечение текста.
- Полноценный семантический поиск / RAG по всему массиву (добавляется модулем при росте объёма).
- Мультипользовательский режим, шаринг, роли и права.
- Повторяющиеся задачи (кроме дат-напоминаний у заметок).
- Локальная модель через Ollama (архитектурно закладываем переключаемость, подключение — после MVP).
- Интеграции с внешними календарями / почтой.

> **Вне продукта (не планируется):** голосовые ответы бота — бот всегда отвечает текстом (см. FR-24).

---

### 5. Основные сущности (глоссарий)

- **Задача** — действие с результатом; имеет приоритет, статус, опциональный дедлайн.
- **Идея** — мысль/замысел на будущее; может дозреть до задачи или проекта.
- **Заметка** — справочная информация (в т.ч. с датой, напр. день рождения); всплывает как контекст.
- **Проект** (= Цель) — контейнер, объединяющий задачи, идеи и заметки; имеет опциональный дедлайн.
- **Сфера (тег)** — метка предметной области; преднастроенные: `работа`, `дом`, `ремонт`, `идеи`; можно добавлять свои; у записи может быть несколько.
- **Инсайты** — вычисляемая ИИ-аналитика на дашборде (не хранимая сущность).

### 6. Функциональные требования (FR)

#### 6.1 Ввод и парсинг («Приёмник»)
- **FR-1.** Приём ввода из TG в трёх форматах: текст, голосовое, изображение.
- **FR-2.** Голос → транскрипция в текст (STT); изображение → извлечение текста (OCR); далее обрабатывается как текст.
- **FR-3.** **По умолчанию исходный медиафайл НЕ сохраняется** — сохраняется только результат его транскрипции/распознавания (текст). Исходный медиафайл сохраняется и привязывается к записи **только по явному запросу пользователя**.
- **FR-4.** ИИ определяет намерение ввода: новая запись / вопрос-команда / правка существующей.
- **FR-5.** При создании ИИ извлекает: тип сущности, суть (заголовок), сферы, проект (если явно следует), дедлайн, приоритет; для заметок — опциональную дату и повтор (напр. «ДР 21 июля» → дата с годовым повтором).
- **FR-6.** Один ввод может быть разбит на несколько записей (пять дел в одной голосовой → пять задач).
- **FR-7.** После создания бот показывает компактную карточку (тип, суть, сфера(ы), проект, дедлайн, приоритет) с действиями «изменить / отменить». Повторно не переспрашивает без необходимости.
- **FR-8.** Ручное прикрепление медиа (картинка/аудио) к любой сущности пользователем.

#### 6.2 Управление сущностями
- **FR-9.** CRUD для Задач, Идей, Заметок, Проектов (в вебе — полный; в TG — создание, смена статуса, лёгкие правки).
- **FR-10.** Задача: суть, опц. описание, приоритет `{ASAP, высокий, средний, низкий}`, статус `{активная, завершённая, отменённая, переданная}`, опц. дедлайн, опц. проект, сферы (0..n), **комментарий (внутренняя хронология выполнения)**, вложения, связи.
- **FR-11.** Статус «переданная» — терминальный, с опциональным текстовым уточнением «кому».
- **FR-12.** Идея: суть, опц. описание, статус `{активная, архивная}`, опц. проект, сферы, комментарий, вложения, связи; может быть преобразована в задачу.
- **FR-13.** Заметка: тело, опц. дата + повтор, сферы, опц. проект, вложения, связи.
- **FR-14.** Проект: наименование, опц. описание, опц. дедлайн, статус, членство задач, идей и заметок, сферы, вложения, комментарий.
- **FR-15.** Сферы: преднастроенный набор (`работа`, `дом`, `ремонт`, `идеи`) + создание пользовательских; назначение нескольких сфер записи.
- **FR-16.** Связи между сущностями (задача ↔ идея ↔ заметка, членство в проекте) — явные, двунаправленные.

#### 6.3 ИИ-ассистент: сценарии
- **FR-17.** «План на день» по запросу:
  1. задачи с дедлайном на сегодня (сортировка по приоритету);
  2. задачи без дедлайна с приоритетом ASAP;
  3. заметки, связанные с сегодняшним днём (напр. ДР сегодня) — как дополнительная информация;
  4. для задач с дедлайном сегодня — подтягивание связанных идей/заметок со ссылкой.
- **FR-18.** «Аналитика дня» по запросу: количество завершённых задач, число идей и прочие агрегаты (напр. в разбивке по сферам/проектам); краткий аналитический вывод.
- **FR-19.** Гибридное связывание: детерминированный костяк (явные ссылки, членство, даты заметок) + ИИ-подсказки вида «эта заметка похоже связана с задачей X — связать?».
- **FR-20.** Смена статуса задачи по сообщению пользователя в TG (бот сам проставляет).
- **FR-21.** Бот НЕ инициирует запрос статуса задач сам, если пользователь явно не попросил.
- **FR-22.** Поиск/выборки по запросу: список по сфере, по проекту, по статусу, текстовый поиск.
- **FR-23.** Слэш-команды как надёжный резерв к ИИ-намерению: `/plan`, `/report`, `/done`, `/find`, `/help` (перечень уточняется в ТЗ).
- **FR-24.** Бот отвечает **только текстом** (голосовые ответы не предусмотрены — ни в MVP, ни далее).

#### 6.4 Веб-кабинет и дашборд
- **FR-25.** Веб — структурированное управление (CRUD всех сущностей), без чат-интерфейса.
- **FR-26.** Дашборд: актуальные и завершённые записи + ИИ-инсайты.
- **FR-27.** Редактирование сущностей и управление связями/членством в проектах.
- **FR-28.** Настройки поведения бота (см. 6.5) доступны и в вебе, и в TG.
- **FR-29.** Синхронизация веб ↔ TG в реальном времени (общая БД — единый источник правды).

#### 6.5 Настройки и уведомления
- **FR-30.** Режим уведомлений: по умолчанию бот отвечает только по запросу.
- **FR-31.** Опция: плановая отправка утреннего отчёта / аналитики дня в заданное время; включение и время настраиваются в TG и в вебе.
- **FR-32.** Часовой пояс пользователя (Барнаул, UTC+7), настраиваемый.

#### 6.6 Авторизация и доступ
- **FR-33.** Веб-кабинет защищён авторизацией по логину и паролю.
- **FR-34.** Доступ к данным — только у авторизованного владельца (никакого доступа по одному лишь знанию URL).

### 7. Ключевые пользовательские сценарии (User Stories)

- **US-1.** Как пользователь, я отправляю боту голосовое «завтра сдать отчёт по фроду и позвонить в ЦОД», чтобы получить две структурированные задачи с дедлайном.
- **US-2.** Как пользователь, я фотографирую записку/доску, чтобы её текст распознался и превратился в задачи/заметки.
- **US-3.** Как пользователь, я прошу «план на день», чтобы увидеть сегодняшние дедлайны, ASAP-задачи и связанный контекст (ДР, связанные заметки).
- **US-4.** Как пользователь, я прошу «итоги дня», чтобы получить аналитику по сделанному.
- **US-5.** Как пользователь, я пишу «отметь задачу X как готово», чтобы бот сменил статус.
- **US-6.** Как пользователь, я захожу в веб-кабинет под логином/паролем, чтобы массово навести порядок и настроить проекты.
- **US-7.** Как пользователь, я включаю утренний отчёт на 08:30, чтобы получать его автоматически.

### 8. Модель данных (состав атрибутов)

Фиксирует **состав**; типы, ограничения и схема связей детализируются в ТЗ.

**Общие атрибуты (все сущности):** `id`, `тип`, `создано`, `изменено`, `сферы[]`, `вложения[]` (извлечённый текст — всегда; исходный файл — только по явному запросу, см. FR-3).

| Сущность | Специфичные атрибуты | Статусы | Связи |
|---|---|---|---|
| **Задача** | суть, описание?, приоритет, дедлайн?, «кому» (для переданной)?, комментарий[] (хронология) | активная / завершённая / отменённая / переданная | проект?, идеи, заметки |
| **Идея** | суть, описание?, комментарий[] (хронология) | активная / архивная | проект?, задачи, заметки |
| **Заметка** | тело, дата?, повтор? | — | проект?, задачи, идеи |
| **Проект** | наименование, описание?, дедлайн?, комментарий[] (хронология) | активный / завершённый / отменённый | состав: задачи + идеи + заметки |
| **Сфера** | наименование, признак «преднастроенная / пользовательская» | — | назначается записям |

*(`?` — атрибут опциональный)*

### 9. Нефункциональные требования (NFR)

- **NFR-1 (Бюджет).** Затраты на ИИ-токены ≤ 1000 ₽/мес при личном профиле нагрузки. Старт — облачные платные модели.
- **NFR-2 (Провайдер-агностичность).** Доступ к LLM через абстракцию/конфиг (OpenAI-совместимый интерфейс); смена провайдера — настройкой, без переписывания бизнес-логики. Задел под Ollama.
- **NFR-3 (Приватность / размещение).** Веб-сервис и бот размещаются на VPS пользователя. Учитывать чувствительность рабочих данных (возможность не отправлять отдельные данные во внешний ИИ — политика уточняется в ТЗ).
- **NFR-4 (Безопасность бэкапа).** Регулярный автоматический бэкап БД с актуальными данными (напр. срез на конец предыдущего дня), **недоступный для изменения/удаления со стороны ИИ/бота** — изолирован от контура автономных действий.
- **NFR-5 (Надёжность данных).** Единый источник правды — общая БД; операции ИИ над данными обратимы/логируемы, чтобы автономность не приводила к необратимой потере.
- **NFR-6 (Локализация).** Язык интерфейса и ответов — русский.
- **NFR-7 (Доступность).** Бот и веб постоянно онлайн на VPS (для планового отчёта и веб-доступа).
- **NFR-8 (Производительность).** Отклик на типовой ввод — интерактивный (целевой ориентир уточняется в ТЗ).

### 10. Ограничения и допущения

**Ограничения:**
- Бюджет ИИ ≤ 1000 ₽/мес.
- Размещение на собственном VPS.
- Оплата облачного ИИ из РФ — фактор выбора провайдера (YandexGPT — рубли/без VPN; DeepSeek — дешевле, но оплата сложнее). Решается в ТЗ.

**Принятые допущения (подтверждены на ревью):**
- **A1.** Медиа-вложения поддерживаются у **всех** сущностей (любой медиа-ввод порождает запись любого типа); при этом исходный файл хранится только по явному запросу (FR-3).
- **A2.** Приоритет — единое поле из 4 значений `{ASAP, высокий, средний, низкий}`; ASAP также служит признаком «показывать в плане дня без дедлайна».
- **A3.** Идея имеет облегчённый жизненный цикл (активная/архивная) и может преобразовываться в задачу; собственного дедлайна у идеи нет (дедлайн — у задач и проектов).
- **A4.** Заметка может нести опциональную структурированную дату с повтором (для ДР и т.п.), которую ИИ извлекает из текста.
- **A5.** «Цель» = Проект (отдельной сущности «цель» не заводим); «инсайты» = вычисляемая ИИ-аналитика, не хранимая сущность.
- **A6.** Тег `идеи` и сущность «Идея» сосуществуют; теги независимы от типа сущности.

---

### 11. Критерии приёмки MVP (AC)

- **AC-1.** Ввод текстом/голосом/картинкой создаёт корректно структурированную запись нужного типа с картой-подтверждением.
- **AC-2.** «План на день» выдаёт сегодняшние дедлайны + ASAP + связанный контекст согласно FR-17.
- **AC-3.** «Аналитика дня» выдаёт агрегаты согласно FR-18.
- **AC-4.** Смена статуса из TG и из веба отражается в обоих каналах (синхронизация).
- **AC-5.** Веб-кабинет недоступен без авторизации.
- **AC-6.** Уведомления по умолчанию выключены; плановый утренний отчёт работает по расписанию при включении.
- **AC-7.** Существует автоматический бэкап, недоступный для изменения ИИ.
- **AC-8.** Смена ИИ-провайдера выполняется настройкой без изменения кода бизнес-логики.

### 12. Что уходит на этап ТЗ (системный анализ)

- Выбор конкретного провайдера/модели (YandexGPT / DeepSeek / Ollama) и сервисов STT/OCR (SpeechKit / Vision или альтернативы).
- Архитектура (компоненты, планировщик), технологический стек, схема БД, внутренние API.
- Механизм изоляции бэкапа от контура автономных действий ИИ.
- Политика приватности данных (что можно/нельзя отправлять во внешний ИИ).
- Декомпозиция на задачи для реализации в Claude Code.
